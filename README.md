# 百趣演武：四张 5 自动抽牌脚本

> **0.2.0 首个集成候选版本：程序入口已接通，实机自动抽牌尚未验收。** 当前本地素材不完整，自动模式会拒绝启动。不要把命令存在或 EXE 能启动理解为实机通过。验证状态见 [PROGRESS.md](PROGRESS.md)。

## 安装与运行

Windows 64 位、Python 3.12。解压源码后在项目目录运行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe ake.py --help
.\.venv\Scripts\python.exe ake.py math
```

EXE 使用相同命令，例如 `AKE.exe math`。它是命令行程序，双击后窗口可能立即关闭，应从 PowerShell 运行。源码和 EXE 使用同一视觉、策略和控制器。

## 校准与素材

在终端运行 `python ake.py calibrate`，看到切换提示后在 10 秒内切回游戏。依次选择五个牌面数字区域、五个库存数值区域、轮次、三个按钮，以及手牌页和放弃弹窗的独特锚点区域。按 Enter 接受，Esc 取消。未显示的弹窗需从实际截图核对区域后，通过 `--layout` 导入准确布局；不要猜测坐标。默认生成 `calibration.local.json`，绑定本次游戏进程、客户区和 DPI。窗口移动、缩放或客户端重启后重新校准。

第一槽选框确定共享模板的裁剪宽高；后四槽只取所选区域的左上角，界面会提示固定尺寸，不缩放牌面图像。导入布局的五槽宽高必须一致，已有牌面模板也须符合该尺寸。新区域在写入前校验；取消或无效区域不会覆盖原配置。

校准与采样配置先写入同目录的唯一临时文件，完成写入和同步后再替换目标，避免写入故障截断已有 JSON。采样先修改配置草稿，保存成功后才更新内存。新生成但未提交的局部素材可能保留在 `logs/calibration-assets`，避免中断后误删已经生效的引用；这些素材及 `.ake-config-*.tmp` 临时文件均受 Git 忽略。

布局 JSON 包含 `frame_size: [宽,高]`、`regions`、`groups` 和 `anchors`。`regions.slots` 与 `regions.inventory` 各为五个 `[x,y,宽,高]`；其余区域名为 `round`、`draw`、`abandon`、`confirm`、`hand` 和 `abandon_dialog`。所有坐标相对客户区。可运行 `calibrate --layout 布局.json --output calibration.local.json` 绑定现有布局，不会发送游戏输入。

采集模板时，用人工确认的真实画面逐类添加，例如：

```powershell
python ake.py sample --profile calibration.local.json --group cards --label 5 --index 0 --batch session-A --score 0.95 --margin 0.1
```

上述阈值仅演示参数格式，必须用标注集校准。`index` 从 0 开始。直接从游戏采样时也会等待最多 10 秒供你切回游戏，不会主动抢焦点。也可传 `--image 原始截图.png`，或 `--recording 录制目录 --at 秒数`，画面尺寸必须与布局相同。库存用独立的 `stock` 组，`--digit` 选择分割出的字符；不会从手牌推算库存。模板写入被 Git 忽略的本地 `logs/calibration-assets`。

必要类别：`cards` 为 `empty,1,2,3,4,5`；`stock` 为字符 `0`–`9`；`round` 为 `1,2`；`draw/abandon/confirm` 为 `enabled,disabled`。锚点使用组名 `hand` 或 `abandon_dialog`，不需要 label。每次 sample 都需要明确 batch、score 和 margin。分类分数不是正确概率。区域和图像形状不匹配或类别不完整时返回未知。

## 只读、回放与自动模式

```powershell
python ake.py observe --profile calibration.local.json --seconds 30
python ake.py run --dry-run --profile calibration.local.json
python ake.py replay 录制目录 --profile 该录像的布局.json
python ake.py validate --profile calibration.local.json --dataset 独立标注.jsonl --output logs/qualification.json
python ake.py run --live --profile calibration.local.json --qualification logs/qualification.json
```

`run` 默认 dry-run，只提出建议，不记录假点击或等待假结果。同一状态不反复输出。`observe` 和 dry-run 用 Ctrl+C 结束；replay 不初始化 Windows 输入或热键。旧实验工具 `replay_cards.py` 已被统一的 `ake.py replay` 取代。

运行开始后，正常结束、Ctrl+C 和采集/识别异常都会输出一次 `summary`，包含终止原因、计数、时间、最后一次观察及 `pending_action`；未确认的发送不能当作已抽到的牌。异常仍返回失败退出码，不会因输出摘要而被当作成功。

确认成功后先停止输入，再保存证据。成功摘要包含 `evidence`、`evidence_seconds` 和 `evidence_error`；保存失败或被 Ctrl+C 中断时，保留 `termination_reason: "success"`，单独输出保存错误并返回失败退出码，继续尝试本地提醒。提醒耗时由 `notification.elapsed` 单列；提醒失败输出 `notification_error`，不会进入游戏画面的错误截图路径。保存和提醒耗时均不计入抽牌总耗时。

校准、采样和验收准备阶段也使用统一的命令行退出边界：Ctrl+C 输出 `stopped` 并退出 0，普通错误输出 `error` 并退出 1；帮助及参数错误保留 argparse 的退出行为。

独立标注文件每行一个 JSON，必须注明 `source: "real"`、与 `training_batches` 不同的 `batch`，以及 `expected` 中完整的 `slots`、`inventory`、`game_round`、`page`、`buttons`。空槽为 0、未知为 null；page 为 `hand/abandon_dialog/unknown`；buttons 按抽牌、放弃、确认排列，值为 `enabled/disabled/null`。来源二选一：静态图片使用相对标注文件的 `image` 路径；录像帧使用相对标注文件的 `recording` 目录和从 0 开始的整数 `frame`，程序直接读取该目录的 `observation.mp4` 与 `frames.csv`，不使用另外导出的图片。

类别覆盖可以使用静态图片；逐张抽牌和未抽满放弃→弹窗→第一轮空牌面、初始库存恢复的流程证据，必须是标注中相邻且来自同批次、同一录像的递增帧。每段录像只顺序扫描一次，并核对完整视频/时间戳记录。重复帧、倒序帧和不存在的帧均拒绝；不同独立帧即使像素相同也可核对。旧的全静态验收集需补齐原始录像帧再验证。录像是否来自当前真实客户端、是否与校准集独立，仍须人工按完整采集批次确认；填写批次名不能替代这项核对。

标注之间的中间帧也会逐帧识别：例如放弃前已出现不同手牌或抽满五张，不能通过跳过该帧证明“未抽满放弃”。已知牌槽、库存或轮次与所标流程冲突时拒绝；未知动画字段继续保留未知，不补全牌面。录像中的人工操作及未知过渡仍需人工核对，程序只核验采样记录中可观察到的状态。

验证集还必须包含未知页、手牌页的未知牌槽和未知库存反例，程序读数须逐字段符合标注；只有正常静止正例不能通过。旧报告的缓存结论不能替代当前素材检查。

同一图片路径不能重复充当不同流程时点，重复项会被拒绝且不计入有效样本数。抽牌和重开序列中的相关按钮必须可用，不能用其他画面的可用按钮样例替代。报告保存原始标注数据集路径；自动启动时重读该数据集并重新验证当前模板和图片，而不直接信任缓存的 `passed` 或指纹。旧报告缺少数据集来源时需重新生成，移动素材后也需更新来源。

自动模式要求类别、区域和锚点完整，并在启动时用当前模板重新通过独立源数据集验证。F8 开始/暂停，F9 终止退出；失焦暂停，不抢前台、不自动恢复。热键注册失败禁止输入。每次只允许一个待确认动作；默认 10 秒未确认就暂停，不补点。恢复须先对齐已发送动作。候选四张 5 冻结后续输入，稳定核对成功后保存牌面并停止。窗口前台检查与系统发送不是原子操作，不能消除全部切换竞态。

F8 启动或恢复后，持续未知、无法取得三帧稳定观察或下一按钮持续不可用，同样在 10 秒后暂停并保存局部证据；等待期间不点击。动作确认后可直接使用该次稳定观察继续决策，提交前仍检查 F8/F9、观察新鲜度和窗口前台。正常连续循环以已确认牌面为计时边界，按钮恢复可用前的等待计入下一抽牌或重开周期；暂停恢复后，首个周期从重新对齐且可提交的稳定观察起算。

实时成本以识别完成的实际单调时刻为边界，包含识别耗时变化；暂停和待确认动作期限也使用实际单调时钟。截图采集时间继续用于独立帧稳定性及 500 毫秒时效检查。回放按原始录像时间轴计算，不受回放速度影响。

候选成功复核从首次观察到候选牌面开始计时，不依赖是否有待确认点击；F8 和失焦暂停不消耗该期限。期限届满仍无法核对时保存疑似成功证据并结束；同一帧已完成稳定成功确认时，优先报告成功。只读观察和回放会输出非空初始牌面，不因此接管或点击。

## 日志、限制与打包

事件日志为 `logs/events.jsonl`，每条含本地带时区时间 `time` 和单调时钟 `monotonic`，每卷 2 MB、最多 3 个备份。成功/错误证据只保存配置的牌槽和库存区域，位于 `logs/evidence`。录屏可能包含其他软件的浮窗；原始录像、模板、日志和校准文件都不上传。证据文件单独保留，需要用户定期归档。

`collect_observation.py` 保留完整客户区尺寸，并把当前已核对布局中包含 UID 的底部 5% 遮黑，保持录像与校准坐标一致。编码要求客户区宽高为偶数；奇数尺寸会明确拒绝，需调整窗口并重新校准。旧的裁高录像应使用符合其实际尺寸的单独布局。回放会核对连续帧号、有限递增时间戳及视频/CSV 一一对应，数据不完整时明确报错。

缺模板、库存不一致、窗口身份变化和验证失败均应先检查素材和校准，不应提高点击频率。首次接管非空手牌只读提示，用户手动返回空牌面后再启动。当前缺少完整库存字符、第二轮及独立实机验收素材，尚不能宣称当前电脑可可靠自动运行。

开发验证：`python -m unittest discover -s tests -v`。打包：在隔离环境安装 `pyinstaller==6.11.1` 后运行 `python -m PyInstaller --clean --noconfirm --onefile --name AKE ake.py`。打包产物仍需做实机验收。

## 1. 任务目标与范围

请开发一个运行于 Windows 的《明日方舟：终末地》“百趣演武”自动抽牌脚本，通过**屏幕截图识别游戏状态，通过鼠标执行抽牌和失败重开操作**。

重点是准确识别、可靠停止、明确规则依据，并在已声明的模型下优化实际耗时。执行本 Prompt 时，先报告现有素材支持什么、还缺什么，再实现和验证；缺少实机素材不妨碍独立数学与离线控制逻辑的开发，但不能据此开启自动输入或宣称实机通过。

### 1.1 已确定的需求

| 项目 | 明确要求 |
|---|---|
| 卡槽 | 每次尝试最多 5 个卡槽 |
| 点数 | 1、2、3、4、5 |
| 初始牌库 | 各点数数量分别为 6、6、6、6、10，合计 34 张 |
| 成功条件 | **同一次尝试的当前手牌中，确认出现至少 4 张点数为 5 的牌** |
| 第五槽 | 可以为空，也可以已经有一张其他点数牌；出现第四张 5 后立即停止，不主动补抽 |
| 优化目标 | 优先缩短从开始尝试到确认成功的**期望实际用时** |
| 运行范围 | 只自动处理游戏中的第 1 轮，即界面 `1/2` |
| 正常失败 | 自动放弃并重新尝试，前提是重开流程已经验证 |
| 默认运行上限 | 不限制尝试次数和总运行时长，直到成功、用户停止或发生异常 |
| 成功后的动作 | 保留牌面，保存证据，发出本地提醒，停止鼠标输入 |
| 不包含 | 点击“开始挑战”、自动战斗、推进第二轮、领取奖励、优化其他牌型 |

成功例子：

- `[5,5,5,5,空]`
- `[1,5,5,5,5]`
- `[5,5,2,5,5]`

不得把四张其他点数、总点数达到 20、界面出现“四条”文字，直接视为目标达成。`[5,5,5,4,1]` 不成功；跨不同尝试累计抽出四张 5 也不成功。

如果启动或恢复时确认四张或五张 5，按数量条件视为成功并停止；正常自动流程应在第四张 5 出现时就结束。首次接管非空且未达标的牌面时只读提示，不自动丢弃或继续这手牌；用户自行回到初始空牌面后再启动。暂停恢复按第 4.3 节核对已经发送的动作。

**本项目的成功指牌面达成，不代表战斗完成、活动任务完成或奖励已经取得。**

### 1.2 开发原则

- 正确性优先于减少等待时间；有疑问就拒绝操作，不猜测牌面。
- 使用真实画面和操作记录校验规则，不把第三方文章或已有代码当作服务器机制证明。
- 区分最少抽牌数、最少重开数、最短实际用时，不声称三者天然一致。
- 首版只完成本任务，不增加通用牌型系统、自动战斗、云服务或图形管理界面。
- 实机素材不足时，完成不依赖这些素材的部分，并明确列出缺口，不伪造模板、验证记录或通过结论。

### 2.2 已有证据及其限制

1. 官方公告确认“百趣演武”为本次活动，但该公告不能证明具体随机算法、锁牌机制或重开后库存。[官方版本公告](https://endfield.gryphline.com/zh-tw/news/9560)
2. 本次活动的一手玩法记录描述了每轮最多抽五次、未抽满即可开始挑战，以及抽牌后的放弃行为。该资料支持逐张决策的可行性，但仍需当前客户端验证。[一手玩法记录](https://mk-chatworks.seesaa.net/article/521892164.html)
3. 第三方开源项目 OEA 已实现“逐张抽牌 → 放弃挑战 → 二次确认 → 等待空牌面”的循环。不过，它会抽满五张才判断，且没有检查牌库是否补满。可以参考其操作流程，不能直接采用其策略，也不能将源码当作游戏服务器规则的证明。[固定版本的抽牌与重开流程](https://github.com/Logical-Byte/open-endfield-assistant/blob/73f75d91a819b45c40d64537b7632d0949b2aa19/src-tauri/src/automation/gamble_battle/worker.rs#L100-L154)
4. 用户提供的截图支持“五个槽位、初始库存、第一轮界面及相关按钮”的识别设计；截图中的牌尚未翻开，**不足以制作完整的点数识别模板或验证重开流程**。

开发时建立规则证据表，分别标记：用户指定的目标、截图可见事实、当前客户端已验证行为、第三方资料描述、数学假设。每项保留来源、适用版本、验证状态和对应截图或录像时间点。

不得直接套用旧版“选剑演武”的攻略规则。不得因为看见五个槽位就认定必须抽满，也不得把 `1/2` 理解为“两次重抽机会”。

### 2.3 自动操作前必须补齐的素材

采集并人工核对以下内容：

- 点数 1～5 的实际牌面、空槽及翻牌动画。
- 右侧库存数字及两位数 `10` 的真实样例，覆盖正常递减过程；牌面点数与库存数字分别制作模板。按数字字符复用素材，不要求先在游戏中出现所有整数库存值。
- 第一轮与第二轮标志。
- 抽牌按钮的可用、不可用状态。
- 放弃按钮、对应确认弹窗。
- 一段完整的“初始空牌面 → 逐张抽牌 → 放弃 → 确认 → 新空牌面”记录。

重开后必须分别验证：

1. 手牌全部清空。
2. 游戏仍处于第一轮。
3. 库存恢复为 `[6,6,6,6,10]`。

不要把“牌槽清空”当作“牌库补满”的证据。不得擅自加入锁牌、保留部分牌、单槽重抽或选择幸运槽位的功能。

自动输入的前提是：窗口校准、所需识别类别、逐张抽牌和完整重开路径均已有当前客户端证据，且相应离线及只读检查通过。资料中的“撤离”“放弃挑战”等文字只作参考，以当前阶段实际按钮和弹窗语义为准。

如果实际流程与资料不同，先记录差异、修正规则和状态转换；证据不足的环节保持只读，不编造按钮坐标或默认通过。库存或操作行为与模型冲突时暂停核实。均匀随机和跨尝试独立属于披露的数学假设，不设置“必须证明服务器算法”这种无法通过有限实测完成的前置条件。

## 3. 抽牌策略与数学要求

### 3.1 数学模型的适用前提

以下计算仅适用于：

- 每张剩余牌被抽中的机会相同。
- 一次尝试内无放回抽牌。
- 每次重开恢复初始牌库。
- 各次尝试相互独立，并服从相同的抽牌模型；库存恢复本身不足以证明这一点。
- 每次抽牌后都能观察结果并决定继续或放弃。
- 不存在额外重开限制或未计入的游戏成本。

前端显示库存递减不能单独证明服务器均匀随机。所有概率和“最优”结论必须附带模型前提。有限实测和模拟不能证明服务器一定采用该模型。

### 3.2 必须实现的基础判断

设 `n` 为当前尝试已确认的手牌数量，`k` 为其中点数为 5 的数量，`j = n-k` 为非 5 的数量。

停止输入与宣告成功是两件事：出现四张 5 的候选牌面时，先冻结后续输入，再完成稳定识别及一致性复核。库存动画暂时滞后时只读等待，不能补抽或重开；复核通过才报告成功，超时或矛盾则保留牌面并报告“疑似达标，待人工核对”。

对完成复核的状态，按以下优先级判断：

| 条件 | 动作 |
|---|---|
| 状态不可靠、观察过期或存在矛盾 | 不发送输入；过渡画面继续观察，确认矛盾或超时后暂停报错 |
| `k ≥ 4` | 成功，立即终止自动操作 |
| `k + (5-n) < 4` | 已不可能成功，执行已验证的重开流程 |
| 仍可能成功 | 根据期望用时策略选择继续或重开 |

在当前规则下，出现第二张非 5 就已不可能成功。只有一张非 5 时仍存在成功机会，是否提前放弃取决于时间成本。

### 3.3 数学基准

从初始空牌面出发，允许继续至五槽时，至少出现四张 5 的概率为：

\[
p=\frac{\binom{10}{4}\binom{24}{1}+\binom{10}{5}}{\binom{34}{5}}
=\frac{441}{23188}\approx1.90184578\%
\]

“第四张 5 出现就停、第二张非 5 出现就重开”的固定基准策略只放弃已经无解的牌面，单次成功率也等于上述 `p`。从初始空牌面开始，在上述模型下有：

| 指标 | 期望值 |
|---|---:|
| 每次尝试抽牌数 | 2.77065724 张 |
| 成功前总尝试次数，包含成功那次 | 52.58049887 次 |
| 成功前重开次数，不含初始进入 | 51.58049887 次 |
| 成功前总抽牌数，包含失败尝试 | 145.68253968 张 |

“首张非 5 就重开”策略的单次成功率为 `21/1364 ≈ 1.53958944%`，成功前期望尝试数为 `1364/21 ≈ 64.95238095`。它会主动放弃部分仍有机会的牌面，因此不能套用基准策略的单次成功率。

这些数值是固定策略的长期期望，不是本次运行还需等待的次数、停止上限或成功保证。中途接管手牌、先采样再切换策略时，不能直接作为整次运行的精确期望。

实现条件成功概率时明确其含义：合法状态 `(k,j)` 下，令 `m=5-k-j`，继续抽取且不主动放弃的成功机会为：

\[
q(k,j)=\sum_{x=4-k}^{\min(m,10-k)}
\frac{\binom{10-k}{x}\binom{24-j}{m-x}}{\binom{34-k-j}{m}}.
\]

已达标取 `1`，已无解取 `0`，不合法的组合数项取 `0`。例如首张非 5 后仍有 `7/1364 ≈ 0.51319648%` 的继续成功机会，但采用立即重开策略时，本次尝试的实际成功率为零。不要将继续机会和策略成功率混为一谈，也不要将每次抽中 5 的概率恒定写成 `10/34` 或虚构槽位优势。

### 3.4 以实际用时选择策略

令：

- `d`：从上一份已确认稳定牌面，到抽牌后获得下一份有效稳定观察的平均周期耗时；首次启动或暂停恢复后，从重新对齐且允许提交的稳定观察起算。
- `r`：从决定放弃所依据的稳定观察完成，到整个放弃、确认流程结束且新空牌面和库存全部确认的平均周期耗时。

周期包含决策、必要日志、输入前检查、点击、动画及识别等待；相邻周期不重复计时。采用单调时钟，被暂停、人工介入或异常打断的周期不纳入成本样本。

在固定 `d > 0`、固定 `r ≥ 0` 模型下，最优策略有两个分支：

| 条件 | 策略 |
|---|---|
| `r/d < 227759/92752 ≈ 2.45556969` | 首张不是 5 就重开；首张为 5 后，出现第二张非 5 再重开 |
| `r/d ≥ 227759/92752` | 保留所有仍可能成功的尝试，出现第二张非 5 再重开 |

两种策略都在第四张 5 被确认后立即停止。阈值处期望用时相同，选择重开次数较少的第二种。

对应期望时间：

\[
T_{\text{首张非5重开}}\approx115.30252101d+63.95238095r
\]

\[
T_{\text{第二张非5重开}}\approx145.68253968d+51.58049887r
\]

实现要求：

- 初始使用“第二张非 5 重开”的基准策略。
- 收集至少 10 次有效抽牌成本样本和 3 次有效重开成本样本后，使用本次运行累计均值选择分支。这只是开始估计的门槛，不代表统计精度足够或实机最优已获证明。
- 仅在新尝试开始时更新策略，避免同一次尝试内因计时波动切换策略。
- 记录成本样本数、均值和标准差；首次运行、窗口重新校准或客户端重启后重新采样。
- 实际总用时从首次有效初始状态确认起，到成功确认止，暂停时间单列；成功后保存截图与提醒的耗时另列。两条理论公式仅针对全程采用相应固定策略的模型，不直接代表先采样再切换策略的整次运行。
- 固定耗时是首版明确采用的近似。如果实测耗时具有明显状态依赖，应如实报告模型限制，不能宣称已达到实机全局最优。

用动态规划及独立策略枚举验证上述结果。状态可用 `(k,j)` 表示：

\[
V(4,j)=0,\qquad V(k,2)=r+V(0,0)
\]

其余非初始状态比较：

\[
V(k,j)=\min\left\{
r+V(0,0),\quad
d+\frac{10-k}{34-k-j}V(k+1,j)
+\frac{24-j}{34-k-j}V(k,j+1)
\right\}
\]

初始空牌面只允许继续抽牌，排除无意义的连续重开。

操作口诀：**四张 5 就停，第二张杂牌必重开；首张杂牌是否重开，看实测重开耗时。**

## 4. 实现方案与操作边界

### 4.1 技术范围和使用接口

首版采用 **Python、本地截图、OpenCV 图像识别和 Windows 鼠标输入**，提供命令行状态输出。只保证经过校准和验收的简体中文游戏窗口配置。

截图使用 MSS；点数、库存数字及按钮使用分区模板识别。牌面点数与右侧库存必须分别读取，不能由手牌推算库存后再声称二者一致。[MSS 文档](https://python-mss.readthedocs.io/stable/)、[OpenCV 模板匹配文档](https://docs.opencv.org/4.x/d4/dc6/tutorial_py_template_matching.html)

鼠标输入统一封装到一个执行器，通过 Windows 输入接口发送；每次输入前检查绑定窗口和当前前台窗口。[SendInput 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)、[前台窗口检查接口](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow)

提供以下接口：

| 接口 | 行为 |
|---|---|
| `calibrate` | 绑定窗口，校准客户区、锚点、识别区域及按钮区域 |
| `observe` | 连续识别并输出状态，不发送输入 |
| `replay` | 按记录的时间、截图和动作事件回放，验证识别与状态转换；不初始化真实输入后端 |
| `run --dry-run` | 默认模式；只输出当前状态的建议，不把建议当成已执行动作、不进入点击后的等待；用户手动改变界面后重新决策，同一状态不重复刷出相同建议 |
| `run --live` | 校验通过后进入待启动状态，由 F8 开始 |
| F8 | 开始或暂停；恢复前重新观察并核验当前状态 |
| F9 | 紧急停止并退出，本次运行不可自动恢复 |

默认不限正常尝试次数和运行时长。识别等待、单步操作等待必须设置超时，默认每步 10 秒；超时进入暂停错误状态，不重发点击。暂停不积累操作超时，但恢复后必须重新观察，不能单靠重置计时解除未确认动作。热键注册失败时禁止进入自动输入模式。

不读取或修改游戏内存，不注入游戏进程，不抓取游戏通信，不增加战斗、云端识别、其他牌型或图形管理界面。

### 4.2 观察数据与视觉校验

视觉观察至少包括：

- 游戏窗口身份、客户区位置和尺寸、观察时间及采集序号。
- 当前页面、游戏轮次 `game_round`。
- 五个槽位的 `空 / 1～5 / 未知` 状态。
- 各点数剩余库存、按钮状态、识别质量。

控制器维护 `draw_count` 和 `attempt_id`：前者从全部已确认槽位导出，后者是脚本的尝试序号，只在首次确认初始状态或确认完整重开后建立新编号。它们与从界面识别的 `game_round` 分开，不能把 `1/2` 当成抽牌次数，也不能每次截图都递增尝试号。

`未知` 不等于 `空`。存在未知槽位时，不把它补成 0，不据此计算概率或生成抽牌动作。模板分数只是匹配指标，不应写成“正确概率”；已确认的旧牌面也不能替代当前被遮挡或过期的观察。

以客户区和视觉锚点定位，禁止把附件坐标直接作为所有电脑通用坐标。窗口移动、缩放、DPI 改变或进程重新创建后暂停，重新核验或校准。同名窗口不得自动继承旧绑定。

每次提交观察需要三次独立采集、相邻间隔至少 100 毫秒的语义一致结果，不能重复使用同一截图凑帧数。对会产生输入的决策，提交时最新截图距离当前时间不得超过 500 毫秒，否则重采集。稳定性仍须满足后置条件，不能仅凭画面不动就认定动画结束。

一次抽牌确认应同时满足：

- 新增且仅新增一张可识别牌。
- 原有手牌保持一致。
- 对应点数库存减少 1，库存总量减少 1。
- 仍位于预期第一轮抽牌界面。

还应满足：对点数 `v`，`剩余库存[v] + 当前手牌中v的数量 = 初始库存[v]`。库存必须来自独立区域识别，不能用此等式生成一个伪装成识别结果的库存值。

动画或库存尚未同步时只读等待；确认矛盾或超时后暂停留证，不猜测补全。四张 5 的候选牌面按第 3.2 节冻结输入，不因等待库存而补抽。数字分类与空槽判断必须允许拒绝识别，不得将最高分候选无条件当作答案。

识别阈值必须在标注集上校准，并用独立样本检验误报和拒绝识别情况，不把参考项目的阈值直接宣称为当前环境已验证参数。

### 4.3 状态机与输入约束

视觉模块只产出观察，策略模块只产出建议，唯一执行器才可发送输入。纯策略与状态转换应能在没有游戏、截图设备和输入权限时测试。

核心转换及其完成条件：

| 当前阶段 | 允许的下一步 | 完成条件 |
|---|---|---|
| 已确认第一轮牌面 | 决策成功、继续或重开 | 观察新鲜可靠，无待确认动作 |
| 已发送抽牌 | 只读等待 | 新增一张且库存变化正确；达标候选先冻结输入 |
| 已发送放弃 | 只读等待 | 出现与本次放弃对应的已验证确认弹窗 |
| 已确认放弃弹窗 | 点击一次确认 | 弹窗与本次放弃动作匹配，确认目标仍有效 |
| 已发送确认 | 只读等待 | 第一轮、五槽全空、初始库存恢复同时成立 |
| 成功或 F9 退出 | 无 | 本次运行终止，F8 不能重新启动 |
| 暂停或错误 | 只读核验 | 故障消除、显式 F8、动作与状态重新对齐后才可恢复 |

允许的游戏操作仅包括：

1. 点击已识别且可用的“抽牌”。
2. 点击当前阶段已验证的“放弃挑战”按钮。
3. 在预期放弃确认弹窗中点击对应确认按钮。

不预设需要退出到大世界再重新进入；以当前版本验证过的实际路径为准。不能把所有弹窗中的“确认”按钮视为可点击目标。

每次只允许存在一个未确认动作，记录唯一动作编号。点击次数不等于抽牌次数。点击后没有变化时，只能等待、重识别或超时暂停，不能连点、补点或改点相邻位置。

成功、暂停、退出、失焦和错误立即取消**尚未发送**的候选动作。**已发送但未确认**的动作保留为待核对记录，不删除、不重发。实际发送输入前重新检查停止标记、状态版本、窗口身份、前台状态和观察时效；等待必须可中断。停止后的输入仅允许释放脚本自己保持的鼠标按压，不允许新的点击。

前台检查和系统发送并非原子操作，应缩短两者之间的间隔，并测试检查前及输入提交边界的失焦情况；不得承诺仅凭一次检查就消除了全部窗口切换竞态。

**一旦确认第四张 5，成功终止优先于继续抽牌和重开。不得存在成功后补发的第五次点击。**

失焦后不抢回前台，也不因重新获得焦点自动恢复。恢复时先用新观察核对已发送动作：符合其唯一后置条件才提交一次结果；界面仍未变化不代表点击肯定未生效，不可据此重发。无法对齐则保持暂停，由用户手动恢复初始牌面后重新启动。人工操作产生的变化不得计入自动点击数，无法重建的历史统计标为未知。

识别到第二轮、战斗画面、未知弹窗或其他页面时停止操作，不自行导航。

“无限尝试”只适用于正常且已确认的失败重开循环；异常不能被当成普通失败而无限重试。

### 4.4 日志和结果

逐动作记录时间、尝试编号、手牌、库存、策略理由、动作及确认结果。成功和错误保存必要区域截图；日志及截图都应避免包含 UID 等无关账号信息。

无限尝试不等于无限积累资源：日志采用轮转保存，普通运行截图只保留有限缓冲；成功和错误证据单独保留。

结果输出包含最终牌面、终止原因、成功证据、各策略采用区间和成本样本。统计分别列出“发送的抽牌点击数”“视觉确认新增的牌数”“确认的新尝试数”“完成的重开数”，不能将点击次数当成抽牌结果；实际用时与暂停时间单列。保存证据失败仍须停止输入，并单独报告保存失败。

本地提醒不得抢占游戏焦点或继续触发游戏操作。发生关键截图、输入、热键或日志故障时先停止输入，再报告错误。

## 5. 测试、交付与完成标准

### 5.1 数学验证

- 精确枚举与超几何公式的结果一致。
- 枚举可达状态，确认所有目标已无解的状态都会重开。
- 验证低、中、高重开成本下的策略及阈值。
- 分别模拟两种固定策略，记录随机种子、样本数和误差范围；数学模拟不调用真实鼠标，也不把两种策略的成功率混用。
- 不以模拟结果证明游戏服务器采用同一随机模型。

### 5.2 视觉和流程验证

使用人工标注、与模板制作素材分离的截图集，覆盖全部点数、空槽、动画、库存数字、两种轮次及确认弹窗。按采集批次划分校准集与验收集，不能将同段录像的相邻帧分到两边充当独立验证。真实和合成样例分别报告，合成通过不能替代真实识别验收。

必须包含以下反例：

| 场景 | 预期结果 |
|---|---|
| `[5,5,5,5,空]` | 成功后无后续输入 |
| `[5,1,5,5,5]` | 成功 |
| `[4,4,4,4,空]` | 不得误报成功 |
| 第一张非 5 | 按选定成本策略处理 |
| 第二张非 5 | 当前尝试已无解，进入重开流程 |
| 点击已生效但动画延迟 | 不重复点击 |
| 点击后立即暂停，恢复时结果才出现 | 保留已发送记录，确认一次，不重发 |
| 卡牌点数和库存变化不一致 | 暂停报错 |
| 第四张 5 已出现但库存仍在更新 | 冻结输入、保留牌面并只读复核，禁止补抽或重开 |
| 牌槽清空但库存未恢复 | 不开始下一次尝试 |
| 第四张 5 出现时已有候选动作 | 候选动作失效 |
| 输入前检查时已失焦或窗口变化 | 检查拒绝发送；另记录检查与发送之间竞态测试的实际边界 |
| 暂停期间人工抽牌 | 恢复前重新核验 |
| 成功后再次按 F8 | 不再启动，不改动成功牌面 |
| dry-run 建议抽牌但无人操作 | 保持只读，不假执行、不产生等待点击结果的超时 |
| 第二轮、战斗、未知弹窗 | 停止，不自动处理 |
| 热键、截图、输入或日志出现关键故障 | 停止输入并报告原因 |

报告各点数识别、拒绝识别和整手牌成功误报的样本数及分母；不只给一个总体准确率。验收集中的错误成功、错误确认重开、未知状态点击、重复点击都必须为 0；样本内零错误不等于实机绝对不会出错。

### 5.3 分阶段验收

1. **离线通过**：数学、状态机、真实截图回放分别验收；缺少真实素材的项目标记未执行，不能用合成样例替代。
2. **只读通过**：在当前客户端持续观察，人工核对手牌、库存、轮次及按钮定位。
3. **操作通过**：验证单次抽牌和完整放弃重开流程，累计至少 10 次正常失败重开循环。若提前成功，立即保留牌面并停止，未完成的循环验收标为待补，不得为凑次数重开成功局。
4. **终止通过**：验证暂停、退出、失焦，以及真实目标牌面出现后保留牌面且停止输入。

各阶段仅按实际记录报告通过、失败或未执行；未观察到真实成功牌面时，将实机成功终止分支标为未验证，不能默认其他阶段已通过，也不能宣称实机端到端全部通过。保留运行环境、素材版本和日志位置，让他人能复核。
